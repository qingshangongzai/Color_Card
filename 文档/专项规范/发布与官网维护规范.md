# 发布与官网维护规范

> 本文为《开发规范.md》拆分出的专项规范，涉及版本发布、更新日志编写、官网内容同步时阅读。

## 1. 更新日志格式规范

### 1.1 版本格式

```markdown
# 🎨 取色卡 v{主版本}.{次版本} 更新日志

## ✨ 新增功能

**{功能模块名称}**
- 新增{功能描述}

## 🔧 问题修复

- 修复{问题描述}

## 🎨 界面优化

- {优化描述}

## 💫 体验优化

- {优化描述}

## ⚡ 性能提升
- {优化描述}
```

### 1.2 分类说明

|  分类  | Emoji | 说明        |
| :---: | :---: | :-------- |
| 新增功能 |   ✨   | 新功能、新特性   |
| 问题修复 |   🔧  | Bug修复     |
| 界面优化 |   🎨  | UI样式、布局调整 |
| 性能提升 |   ⚡   | 性能优化      |
| 代码重构 |  🏗️  | 代码结构调整    |

**注意：** 分类可根据实际更新内容灵活调整，只需保持格式正确（`## Emoji 分类名称`）即可。

### 1.3 内容规范

- **功能模块分组**：将相关功能按模块分组，使用粗体标注模块名称
- **表述规范**：使用动词开头（新增、修复、优化、调整、重构），描述简洁清晰
- **条目排序**：同一分类内按重要性排序

### 1.4 示例

```markdown
# 🎨 取色卡 v1.2 更新日志

## ✨ 新增功能

**色彩分析增强**
- 新增色彩分析页面高饱和度/高明度区域显示功能
- RGB直方图添加通道切换按钮

## 🔧 问题修复

- 修复全屏按钮窗口状态保存问题
- 修复Win10深色模式适配问题

## 🎨 界面优化

- 优化图标和交互体验

## ⚡ 性能提升

- 优化应用启动速度
```

## 3. 更新日志维护

**配置文件：**

- **公开日志**：`docs/changelog.json` 和 `website/public/changelog.json`（网站展示）
- **应用内日志**：`app_log/changelog.json`（应用内更新对话框）

**数据格式：**

```json
{
  "versions": [
    {
      "version": "v1.9.0",
      "date": "2026-04-26",
      "notes": [
        "Windows版本对配置文件区分了安装版与便携版...",
        "Mac 版本在这个版本出现了一些兼容性而导致闪退的问题..."
      ],
      "changes": [
        {"category": "新增功能", "items": [{"title": "功能名称", "desc": "功能描述"}]},
        {"category": "问题修复", "items": ["修复问题描述"]}
      ]
    }
  ]
}
```

**字段说明：**

| 字段         |   类型   | 说明                                      |
| :----------- | :------: | :---------------------------------------- |
| `version`    | string  | 版本号                                    |
| `date`       | string  | 发布日期（YYYY-MM-DD）                     |
| `notes`      |  array  | 通知列表（可选），仅应用内日志支持          |
| `changes`    |  array  | 更新内容列表                               |
| `category`   | string  | 分类名称（问题修复/界面优化/新增功能等）     |
| `items`      |  array  | 条目列表，简单条目用字符串，复杂条目用对象   |
| `desc`       | string  | 复杂条目的功能描述，支持 `<br>` 分隔多行内容 |

**公开日志与应用内日志的区别：**

| 特性         | 公开日志 (`docs/changelog.json`) | 应用内日志 (`app_log/changelog.json`) |
| :----------- | :------------------------------- | :------------------------------------ |
| 用途         | 网站展示                          | 应用内更新对话框                        |
| 受众         | 所有访客                          | 已安装用户                             |
| 内容         | 功能介绍、优化项                   | 技术细节、临时通知、已知问题             |
| 通知字段     | ❌ 无                             | ✅ 有 `notes` 字段                     |
| 敏感信息     | ❌ 不应包含                       | ✅ 可以包含                            |

**维护要求：**

1. 发布新版本时，先更新 `app_log/changelog.json`（添加应用内通知）
2. 再更新 `docs/changelog.json` 和 `website/public/changelog.json`（公开日志，去掉敏感信息）
3. 保持公开日志两个文件同步（docs 和 website/public）
4. 分类名称与本文 §1.2 更新日志分类保持一致

**获取逻辑：** 应用优先获取 `app_log/changelog.json`，失败时降级到 `docs/changelog.json`。

## 4. 截图更新

**截图存放位置：** `docs/screenshots/` 和 `website/public/screenshots/`

**截图尺寸建议：** 宽度 1200-1920px；格式 PNG；命名使用小写英文字母，如 `color-extract.png`

**更新步骤：** 替换 `website/public/screenshots/` 中的图片；同步复制到 `docs/screenshots/`；刷新网页查看效果。

## 5. 部署流程

**自动部署：** 推送代码到 GitHub 后自动触发 GitHub Actions 部署；部署源：`docs/` 目录

**手动同步文件：**

```bash
Copy-Item website\public\changelog.json docs\changelog.json -Force
Copy-Item website\public\screenshots\* docs\screenshots\ -Force
```

## 6. 注意事项

- JSON 文件中避免使用中文引号
- 截图文件不要过大，建议压缩后上传
- 更新日志保持简洁，突出重点
- 确保两个目录的文件保持同步
