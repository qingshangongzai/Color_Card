## 1. 概述

### 1.1 项目简介

取色卡（Color Card）是一个基于 PySide6 开发的图片颜色分析工具，用于从图片中提取颜色信息和分析明度分布，支持多种色彩模式显示。

**核心功能：**

- 图片导入（JPG、PNG、BMP、GIF）
- 色彩分析：可拖动取色点，实时显示色彩值
- 多色彩模式：HSB、LAB、HSL、CMYK、RGB
- 明度分析与直方图可视化
- 双面板数据同步

### 1.2 开发环境

- **操作系统**：Windows 10/11
- **Python 版本**：3.11+
- **GUI 框架**：PySide6 + PySide6-Fluent-Widgets
- **推荐 IDE**：VS Code、PyCharm、Trae

### 2.4 资源路径规范

**打包兼容性要求：**

项目支持使用 **Nuitka** 或 **PyInstaller** 打包为独立可执行文件，资源路径获取必须兼容开发环境和打包后的环境。

**路径获取函数：** 使用 `get_base_path()` 获取应用程序基础路径（**权威定义位于 `utils/icon.py`**，经 `utils` 包导出，其他模块一律 `from utils.icon import get_base_path`，禁止再复制定义。`main.py` 因启动顺序保留本地私有实现，属唯一例外），支持开发环境和打包后的环境。

```python
def get_base_path() -> str:
    """获取应用程序基础路径

    支持开发环境、PyInstaller 和 Nuitka 打包后的环境

    Returns:
        str: 应用程序基础路径
    """
    if getattr(sys, 'frozen', False):
        # 打包后的环境（PyInstaller 或 Nuitka）
        if hasattr(sys, '_MEIPASS'):
            # PyInstaller 单文件模式
            return sys._MEIPASS
        # Nuitka 或 PyInstaller 单目录模式
        return os.path.dirname(sys.executable)
    # 开发环境 - 返回项目根目录
    return os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
```

**使用规范：**

- 所有资源文件路径必须通过 `get_base_path()` 获取
- 禁止直接使用 `__file__` 获取项目根目录（打包后会失效）

```python
# 正确用法
base_path = get_base_path()
locales_dir = os.path.join(base_path, 'locales')

# 错误用法 - 打包后会找不到资源
project_root = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
```

### 3.7 类型注解规范

**基本原则：** 项目要求 Python 3.11+，使用 PEP 585 内置泛型语法；避免使用 `typing` 模块中已弃用的类型（如 `typing.List`、`typing.Dict` 等）；公共方法应添加返回类型注解。

**类型对照表：**

| typing 旧类型（避免） |    内置泛型（推荐）    | 说明   |
| :----------: | :--------------: | :--- |
| `List[元素类型]` | `list[元素类型]`     | 列表类型 |
| `Dict[键类型, 值类型]` | `dict[键类型, 值类型]` | 字典类型 |
| `Tuple[元素类型, ...]` | `tuple[元素类型, ...]` | 元组类型 |
| `Optional[T]` |   `T \| None`    | 可选类型 |
|  `Type[类名]`  | `type[类名]`       | 类型对象 |

```python
from typing import Any

def get_colors(self) -> list[str]:
    return ['#FF5733', '#33FF57']

def get_config(self) -> dict[str, Any]:
    return {'name': 'test', 'value': 123}

def find_item(self, item_id: str) -> dict[str, Any] | None:
    return None  # 或返回字典
```

### 3.7.1 Nuitka 打包兼容性要求

**核心原则：使用 PEP 585 内置泛型（如 `list[int]`、`dict[str, Any]`）的文件，必须在顶部添加 `from __future__ import annotations`。**

**原因：** Nuitka 编译后内置类型变为 C 层面的 `compiled_function`，直接对注解求值（如 `set[int]`）会触发 `TypeError` 导致启动闪退。`from __future__ import annotations` 将注解转为字符串延迟求值，规避此问题。

**判断是否需要添加：**

| 使用的类型注解 | 是否需要 |
| :---: | :---: |
| 仅简单类型（`str`、`int`、`bool`、`float`、`None`） | ❌ |
| PEP 585 泛型（`list[...]`、`dict[...]`、`set[...]`、`tuple[...]`） | ✅ 必须 |
| 旧式 typing 名称（`Tuple`、`List` 等）且未 import | ✅ 建议 |

`from __future__ import annotations` 必须放在文件最顶部（文档字符串之后，所有导入之前）。

### 3.8 主题与样式规范

#### 3.8.1 主题切换实现规范

**使用 qfluentwidgets 的主题系统：** 使用 `setTheme(Theme.LIGHT/DARK)` 切换主题；使用 `isDarkTheme()` 检测当前主题；使用 `qconfig.themeChangedFinished` 信号监听主题变化。

```python
from qfluentwidgets import setTheme, Theme, isDarkTheme, qconfig

# 切换主题
def toggle_theme():
    setTheme(Theme.DARK if isDarkTheme() else Theme.LIGHT)

# 监听主题变化
qconfig.themeChangedFinished.connect(self._update_styles)
```

#### 3.8.2 颜色管理规范

**集中管理颜色值：** 所有颜色值应定义在 `theme_colors.py` 中；使用函数返回 QColor，支持主题感知；避免在组件中硬编码颜色值。

```python
def get_card_background_color():
    return QColor(42, 42, 42) if isDarkTheme() else QColor(255, 255, 255)

def get_text_color(secondary=False):
    if isDarkTheme():
        return QColor(160, 160, 160) if secondary else QColor(255, 255, 255)
    else:
        return QColor(120, 120, 120) if secondary else QColor(40, 40, 40)
```

#### 3.8.3 主题自适应组件实现

**必须实现** `_update_styles()` 方法：在 `__init__` 中调用 `_update_styles()` 初始化样式；连接 `qconfig.themeChangedFinished` 信号；根据 `isDarkTheme()` 返回不同颜色值。

```python
class MyWidget(QWidget):
    def __init__(self, parent=None):
        super().__init__(parent)
        self.setup_ui()
        self._update_styles()
        qconfig.themeChangedFinished.connect(self._update_styles)

    def _update_styles(self):
        """更新样式以适配主题"""
        label_color = "#ffffff" if isDarkTheme() else "#333333"
        self.label.setStyleSheet(f"color: {label_color};")
```

**注意事项：** `_update_styles()` 中只更新必要的文字颜色，避免调用 `setStyleSheet` 设置容器样式；让 qfluentwidgets 原生机制处理主题切换。

#### 3.8.4 样式表使用规范

**避免使用** `!important`：优先使用组件特定的选择器；如必须使用，确保在主题切换后重新应用。

### 4.3.1 跨面板图片同步（直接信号连接，已替代 ImageMediator）

~~ImageMediator 中介者模式已被废弃~~，改用面板间直接信号连接，更简洁直观：

```python
class ColorAnalysisInterface(QWidget):
    # 定义同步信号（替代中介者转发）
    image_sync_requested = Signal(object, object)  # QPixmap, QImage
    clear_sync_requested = Signal()

    def on_image_loaded(self, file_path):
        """图片加载完成，直接发射同步信号给另一面板"""
        pixmap = self.image_canvas._original_pixmap
        image = self.image_canvas._image
        if pixmap and image and not pixmap.isNull() and not image.isNull():
            self.image_sync_requested.emit(pixmap, image)

    def on_image_cleared(self):
        """图片清空，同步通知另一面板"""
        self.clear_sync_requested.emit()

    def set_image_data(self, pixmap, image, emit_sync=True):
        """接收来自另一面板的图片数据，emit_sync=False 防止循环"""
        self.image_canvas.set_image_data(pixmap, image, emit_sync=emit_sync)
```

**主窗口连接跨面板信号（替代中介者）：**

```python
def _setup_cross_panel_sync(self):
    """设置跨面板图片同步（直接连接，替代 ImageMediator）"""
    color_interface = self._get_interface('colorAnalysis')
    luminance_interface = self._get_interface('luminanceAnalysis')

    # 色彩 → 明度
    color_interface.image_sync_requested.connect(
        lambda p, i: luminance_interface.set_image_data(p, i, emit_sync=False)
    )
    color_interface.clear_sync_requested.connect(
        lambda: luminance_interface.clear_all(emit_signal=False)
    )

    # 明度 → 色彩
    luminance_interface.image_sync_requested.connect(
        lambda p, i: color_interface.set_image_data(p, i, emit_sync=False)
    )
    luminance_interface.clear_sync_requested.connect(
        lambda: color_interface.clear_all(emit_signal=False)
    )
```

**清空同步规范：** 界面类应提供 `clear_all(emit_signal=True)` 方法统一处理所有清空操作，通过 `emit_signal` 参数控制是否触发同步，防止循环。

## 6. 重构规范

### 6.1 重构原则

1. **保持功能不变**：重构过程中不改变现有功能
2. **渐进式重构**：分阶段进行，每阶段可独立验证
3. **先整理后重构**：先规范现有代码，再提取基类，最后重组目录
4. **代码清理同步**：修改代码时同步清理相关重复代码

### 6.2 基类提取规范

**步骤：** 分析相似组件的公共逻辑；设计基类接口（抽象方法）；迁移第一个子类，验证基类设计；迁移其他子类；全面测试验证。

```python
# 基类定义
class BaseCanvas(QWidget):
    def _draw_overlay(self, painter: QPainter):
        """绘制叠加内容（子类必须实现）"""
        raise NotImplementedError("子类必须实现 _draw_overlay 方法")

# 子类实现
class ImageCanvas(BaseCanvas):
    def _draw_overlay(self, painter: QPainter):
        # 具体实现...
```

> 基类接口细节见《专项规范/基类设计规范》。

### 6.3 模块合并规范

**合并原则：** 将紧密相关的类合并到同一文件；避免过度拆分，提高代码可维护性；保持模块化，但减少文件数量。

**示例：** `cards.py` 合并 ColorCard、LuminanceCard 及相关基类；`histograms.py` 合并直方图组件及基类；`canvases.py` 合并画布组件及基类。

### 8.7 线程安全测试

```python
def test_cancel_does_not_block(qtbot):
    """测试 cancel() 不阻塞调用线程"""
    calculator = HistogramCalculator(image, "luminance")
    calculator.start()
    
    import time
    start_time = time.time()
    calculator.cancel()
    elapsed = time.time() - start_time
    
    assert elapsed < 0.01  # cancel 应该在 10ms 内返回
    calculator.wait(1000)
```

## 9. AI 协作规范

### 9.1 定位

**AI 生成的代码等同于新人提交的 PR**：不因生成速度快而降低审查标准；合入前必须经过 code-review 流程（见 `skills/code-review`）。

### 9.2 审查三问

任何涉及以下三类改动的代码，合入前必须能讲清楚**实际行为**，讲不清楚即打回：

1. **异步时序**：QThread / 信号槽 / QTimer 的触发顺序、取消与竞态——"信号什么时候发、谁先谁后、线程退出时会发生什么"
2. **边界与异常**：空图片、超界坐标、文件读写失败等边界输入的实际走向——"最坏输入进来，代码走到哪一步"
3. **核心算法**：颜色转换、直方图、Zone 分区、配色生成等算法的数学含义——"这个公式算出来是什么、为什么正确"

### 9.3 人机分工

- **用户负责**：需求与方案级决策（选型取舍、行为边界、数据语义）、审查裁决
- **AI 负责**：执行实现、运行测试、按 skill 流程产出（审查报告、提交信息、方案文档）
- 方案级决策必须用户拍板，AI 不得替用户决定，也不得自主发起方案重写

### 9.4 产出物要求

- 审查结论、测试结论必须锚定实际命令输出（pytest / mypy / ruff 的退出码与输出），禁止凭推断断言"已通过"
- 涉及第三方库 API 签名或运行时行为时，读 `site-packages/` 实际源码或官方文档验证，禁止凭记忆断言
- 跨会话方案文档遵循 `skills/plan-doc` 的接力规则：只追加、不重写，断点写落地记录
