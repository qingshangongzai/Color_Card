# Color Card 开发经验总结

## 1. 配色生成功能开发经验

### 1.1 算法设计原则

**配色生成算法参数设计：**

- 不同配色方案的采样点数量应根据色彩理论确定
- 同色系：4个（同一色相，不同饱和度）
- 邻近色：4个（基准色±30°范围内）
- 互补色：5个（基准色一侧3个，互补色一侧2个）
- 分离补色：3个（基准色+两个分离补色）
- 双补色：4个（两组互补色）

**饱和度参数设计：**

- 所有配色生成函数应接受 `base_saturation` 参数（默认100）
- 基于基准饱和度生成变化的饱和度序列，而非固定值
- 保持色彩和谐性的同时，支持随机饱和度变化

```python
def generate_monochromatic(hue: float, count: int = 4, base_saturation: float = 100):
    saturations = [
        base_saturation,
        max(20, base_saturation * 0.75),
        max(20, base_saturation * 0.5),
        max(20, base_saturation * 0.25)
    ]
```

**算法实现注意事项：**

- 函数签名要统一，避免参数错位（如 `angle` 和 `count` 的顺序）
- 使用明确的 `if-elif` 分支调用不同生成器，而非字典映射
- 色相计算注意取模运算 `(hue + 180) % 360`
- 饱和度计算确保最小值不低于20，保证颜色可见性

## 2. 布局设计最佳实践

### 2.1 工具栏/按钮容器间距规范

- 工具栏容器应该设置合理的边距，避免按钮紧贴边缘
- 推荐设置：`setContentsMargins(0, 8, 0, 8)` 给上下留出 8px 间距
- 容器高度应该与边距协调，如边距 8px 时，最大高度应 >= 50px

```python
toolbar = QWidget()
toolbar.setMaximumHeight(50)
toolbar.setStyleSheet("background: transparent;")
layout = QHBoxLayout(toolbar)
layout.setContentsMargins(0, 8, 0, 8)
layout.setSpacing(10)
```

### 2.2 布局拉伸与对齐的冲突

- `layout.setAlignment(Qt.AlignmentFlag.AlignCenter)` 会阻止子控件拉伸填满父布局
- 需要拉伸填满时，应移除对齐设置，使用 `stretch` 参数控制比例

```python
layout.addWidget(widget, stretch=1)
```

### 2.3 多层嵌套布局的拉伸传递

- 每一层布局都需要设置 `stretch` 参数，才能让拉伸效果传递到最内层控件

```python
outer_layout.addWidget(inner_container, stretch=1)
inner_layout.addWidget(actual_widget, stretch=1)
```

### 2.4 渐进式压缩设计原则

当窗口需要被压缩到很小时，应该设计多层次的压缩策略：

1. **第一阶段：正常压缩**
   - 保持所有内容可见，按比例缩小各区域
   - 设置合理的 `minimumHeight`，确保基本可读性

2. **第二阶段：紧凑模式**
   - 降低 `minimumHeight` 到更小值（如从160降到120）
   - 减小间距（`setSpacing` 从5降到3）
   - 减小边距（`setContentsMargins` 减小）
   - 缩小控件尺寸（按钮高度从28降到24）

3. **第三阶段：极限压缩**
   - 使用 `QScrollArea` 包裹内容
   - 或者隐藏非关键信息
   - 设置窗口绝对最小尺寸 `setMinimumSize()`

**关键经验：**

- 不要只降低一个组件的最小高度，要**整体协调降低**
- 压缩时同步减小**间距、边距、控件尺寸**
- 测试时应该**逐步压缩窗口**，观察每个阶段的显示效果

## 4. 导入导出功能开发经验

### 4.1 JSON数据格式设计

- 包含版本号便于后续数据迁移
- 包含导出时间戳便于追踪
- 数据与元数据分离

```python
def export_favorites(self, file_path: str) -> bool:
    favorites = self.get('favorites', [])
    export_data = {
        "version": "1.0",
        "export_time": datetime.now().isoformat(),
        "favorites": favorites
    }
    with open(file_path, 'w', encoding='utf-8') as f:
        json.dump(export_data, f, ensure_ascii=False, indent=2)
```

### 4.2 导入模式选择

- 提供追加和替换两种模式
- 使用MessageBox进行用户确认
- 数据验证后再导入

```python
def import_favorites(self, file_path: str, mode: str = 'append') -> tuple:
    try:
        with open(file_path, 'r', encoding='utf-8') as f:
            data = json.load(f)

        if 'favorites' not in data:
            return False, 0, "无效的数据格式"

        imported = data['favorites']

        if mode == 'replace':
            self.set('favorites', imported)
        else:
            existing = self.get('favorites', [])
            existing.extend(imported)
            self.set('favorites', existing)

        self.save()
        return True, len(imported), ""
    except (OSError, json.JSONDecodeError) as e:
        return False, 0, str(e)
```

## 7. 内置色彩多段显示经验

### 7.1 问题背景

内置色彩面板中的配色颜色数量不一（4-24个），需要在有限空间内合理显示所有颜色。

### 7.2 显示模式分类

| 显示模式 | 适用场景 | 颜色分配 | 切换方式 |
|:---:|:---|:---|:---|
| `single` | 颜色数量少（≤4个） | 直接显示所有颜色 | 无切换按钮 |
| `sequential` | 标准顺序色（10-12个） | 两段均分显示 | 浅色组/深色组切换 |
| `triple` | 颜色较多（12-16个） | 三段均分显示 | 前半/中间/后半循环切换 |
| `quad` | 颜色很多（24个） | 四段均分显示（每段6个） | 第一段/第二段/第三段/第四段循环切换 |
| `diverging` | 发散色（ColorBrewer） | 以中间为界分左右 | 左半/右半切换 |
| `qualitative` | 定性色（ColorBrewer） | 两段均分显示 | 前半/后半切换 |

### 7.3 实现要点

**动态分配颜色数量：**

```python
half_count = total_colors // 2
if self._shade_mode == 'light':
    colors = [colors_dict.get(i, '') for i in range(half_count)]
else:
    colors = [colors_dict.get(i, '') for i in range(half_count, total_colors)]
```

**系列类型判断：**

```python
def _get_series_type(self) -> str:
    if self._series_key.startswith(('catppuccin', 'gruvbox')):
        return 'quad'
    if self._series_key.startswith(('rose_pine', 'solarized')):

    if self._series_key.startswith(('nord', 'dracula')):
```

### 7.4 关键经验

1. **根据颜色数量选择显示模式**
   - ≤4个颜色：使用 `single` 模式
   - 5-10个颜色：使用 `sequential` 模式
   - 11-16个颜色：使用 `triple` 模式
   - ≥20个颜色：使用 `quad` 模式

2. **保持切换按钮一致性**
   - 除 `single` 模式外，其他模式都显示切换按钮
   - 按钮使用循环切换逻辑

3. **动态计算优于固定值**
   - 使用 `total_colors // n` 计算每段数量，而非硬编码

## 8. 多线程开发经验

### 8.1 信号连接类型规范

**跨线程信号必须使用 QueuedConnection**

```python
# ✅ 正确：跨线程信号使用 QueuedConnection
calculator.finished.connect(
    self._on_finished, Qt.ConnectionType.QueuedConnection
)
calculator.error.connect(
    self._on_error, Qt.ConnectionType.QueuedConnection
)
```

**原因：**

- DirectConnection 会在发射信号的线程中执行槽函数
- QueuedConnection 确保槽函数在接收者所在线程执行
- 跨线程 UI 更新必须使用 QueuedConnection

### 8.2 QImage 数据安全

**QImage 必须复制后传递给子线程**

```python
# ❌ 错误：直接引用，主线程可能修改或释放
self._image = image

# ✅ 正确：复制数据，避免主线程影响
self._image = image.copy() if image and not image.isNull() else None
```

**原因：**

- QImage 是隐式共享的，但不是线程安全的
- 主线程释放图片后，子线程访问会导致崩溃
- copy() 创建独立副本，确保数据安全

### 8.3 线程安全退出

**禁止使用 terminate()**

```python
# ❌ 错误：强制终止线程
if calculator.isRunning():
    calculator.terminate()
    calculator.wait(100)

# ✅ 正确：等待线程自然退出
calculator.cancel()
if calculator.isRunning():
    calculator.wait(500)  # 给予足够时间退出
# 如果仍在运行，让它在后台自然结束
```

**原因：**

- terminate() 立即终止线程，不释放资源
- 可能导致死锁、内存泄漏、数据损坏
- 使用 cancel() + wait() 优雅退出

### 8.4 服务类析构函数

**服务类必须添加析构函数确保线程退出**

```python
def __del__(self):
    """析构函数：确保所有线程在对象销毁前停止"""
    self.cancel_all()
    for calculator in [self._calculator1, self._calculator2]:
        if calculator is not None and calculator.isRunning():
            calculator.wait(1000)
```

**原因：**

- Python GC 不保证及时回收
- QThread 销毁时仍在运行会报错
- 析构函数确保资源正确释放

### 8.5 线程类文档注释规范

**完整的线程类文档应包含：**

```python
class HistogramCalculator(QThread):
    """直方图计算线程

    在后台线程中执行直方图计算，避免阻塞 UI 线程。
    支持明度直方图、RGB 直方图、色相直方图计算。

    线程安全说明：
    - 所有信号都使用 QueuedConnection，确保跨线程安全
    - QImage 数据在构造时复制，避免主线程修改
    - cancel() 方法设置标志位，不阻塞调用线程
    - 不使用 terminate()，通过标志位优雅退出

    使用示例：
        calculator = HistogramCalculator(image, "luminance", parent=self)
        calculator.finished.connect(
            self._on_finished, Qt.ConnectionType.QueuedConnection
        )
        calculator.start()

        # 取消计算
        calculator.cancel()

    信号:
        finished: 计算完成时发射，参数为计算结果
        error: 计算出错时发射，参数为错误信息
    """
```

### 8.6 关键经验总结

| 问题 | 解决方案 |
|------|----------|
| cancel() 阻塞 UI | 只设置标志位，不调用 wait() |
| 跨线程信号崩溃 | 使用 QueuedConnection |
| QImage 访问崩溃 | 构造时 copy() 图片 |
| terminate() 崩溃 | 使用 cancel() + wait() 优雅退出 |
| 线程销毁警告 | 服务类添加 __del__ 析构函数 |
| 对话框主题信号未断开 | 继承 BaseFramelessDialog，基类 closeEvent 自动断开 |

## 9. 无边框窗口常见问题

对话框统一继承 `BaseFramelessDialog`（`dialogs/base_frameless_dialog.py`），由基类提供标题栏、主题适配和信号断开。以下是改造过程中积累的常见问题与解决方案：

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 标题栏和内容重叠 | 未为标题栏留出空间 | 设置 `layout.setContentsMargins(20, 40, 20, 20)` |
| 背景色不生效 | FramelessDialog 不使用样式表设置背景 | 使用 `QPalette` + `setAutoFillBackground(True)` |
| 标题颜色不随主题切换 | 样式表未应用到标题栏控件 | 直接为标题标签设置样式表，并在 `_update_styles` 中更新 |
| 关闭按钮颜色不随主题切换 | 未设置关闭按钮的颜色属性 | 使用 `closeBtn.setNormalColor()` 等方法设置 |
| Logo/标题/按钮挤在一起 | 清除了原有布局的所有项 | 保留原有布局，只在开头插入新控件 |
| 标题紧贴左边框 | 未设置左边距 | 添加固定宽度的占位符 QLabel |
| 从子控件打开对话框时背景色异常 | 父窗口不是顶层窗口 | 使用 `parent=self.window()` 而不是 `parent=self` |
| 出现两套窗口控制器（最小化/最大化/关闭按钮） | 父控件不是窗口，导致 Windows 显示系统按钮 | 确保 `parent` 参数传入顶层窗口（`self.window()`） |
| 深色模式下背景仍为白色/灰色 | `QPalette` 设置时机不对或父窗口问题 | 1. 确保使用 `QPalette` + `setAutoFillBackground(True)` 设置背景<br>2. 确保父窗口是顶层窗口<br>3. 在 `_update_styles` 中设置，而非 `__init__` 中 |

## 11. 代码审查经验

### 11.1 重复代码处理原则

**不应该抽象的重复：**

- 标准库/框架的惯用写法（如 `try/except` 信号断开）
- 只有 6 处以下且场景简单
- 抽象后反而降低可读性

**应该抽象的重复：**

```python
def safe_disconnect(signal, slot):
    try:
        signal.disconnect(slot)

        pass

# ✅ 维持现状：标准 try/except 写法

    signal.disconnect(slot)
except (TypeError, RuntimeError):
    pass
```

## 13. 适度防御性设计实践

### 13.1 什么是适度防御

根据项目开发规范：
> **"边界检查要有实际意义"**

**过度防御的表现：**

- 重复验证同一条件
- 对内部可控调用进行过度验证
- 为已完成的迁移保留兼容代码
- 对几乎不会出错的操作包裹 try-except

### 13.2 过度防御案例分析

#### 案例 1：不必要的异常处理

**❌ 过度防御：**
```python
def get_system_language(self) -> str:
    try:
        system_locale = QLocale.system().name()
        if system_locale in SYSTEM_LANGUAGE_MAPPING:
            return SYSTEM_LANGUAGE_MAPPING[system_locale]
    except (AttributeError, ValueError):
        pass
    return self.FALLBACK_LANGUAGE
```

**✅ 适度防御：**
```python
def get_system_language(self) -> str:
    system_locale = QLocale.system().name()
    return SYSTEM_LANGUAGE_MAPPING.get(
        system_locale,
        SYSTEM_LANGUAGE_MAPPING.get(system_locale.split('_')[0], self.FALLBACK_LANGUAGE)
    )
```

**理由：** `QLocale.system().name()` 几乎不会抛出异常，try-except 是过度防御。

#### 案例 2：自动扩展列表掩盖逻辑错误

**❌ 过度防御：**
```python
def update_sample_point(self, index, rgb):
    if index < 0:
        return
    # 自动扩展列表掩盖了调用逻辑错误
    while len(self._sample_colors) <= index:
        self._sample_colors.append((128, 128, 128))
    self._sample_colors[index] = rgb
```

**✅ 适度防御：**
```python
def update_sample_point(self, index, rgb):
    if not (0 <= index < len(self._sample_colors)):
        return
    self._sample_colors[index] = rgb
```

**理由：** 自动扩展列表掩盖了调用方传入错误索引的问题，应该让调用失败暴露问题。

#### 案例 3：重复的图片有效性检查

**❌ 过度防御：**
```python
if self._image and not self._image.isNull():
    # 处理图片
```

**✅ 适度防御：**
```python
if self._image:
    # 处理图片
```

**理由：** 空 `QImage` 对象是 falsy 值，`isNull()` 检查在大多数情况下是多余的。

### 13.3 必要的防御性编程

**以下情况需要保留防御性检查：**

#### 1. 浮点数精度问题
```python
# 必须保留：浮点数计算存在精度误差
orig_x = max(0, min(orig_x, self._image.width() - 1))
```

#### 2. 多线程竞态条件
```python
# 必须保留：子线程可能已断开信号
try:
    self._calculator.calculation_finished.disconnect(self._on_calculation_finished)
except RuntimeError:
    pass  # 信号可能已在其他路径中断开
```

#### 3. 外部数据来源
```python
# 必须保留：用户可能随时清除图片
image = canvas.get_image()
if image and not image.isNull():
    widget.set_image(image)
```

### 13.4 修复经验总结

**本次修复统计（2026-03-29）：**

| 类别 | 数量 | 处理方式 |
|------|------|----------|
| 已修复的过度防御 | 11 处 | 简化代码，移除冗余检查 |
| 确认合理的设计 | 8 处 | 维持现状，保留必要检查 |

**主要修复内容：**

1. **简化异常处理** - 移除不必要的 try-except，使用更简洁的逻辑
2. **移除自动扩展** - 让错误暴露，而不是静默处理

### 14.5 覆盖升级判断逻辑

**问题**：如何区分"安装程序"和"已安装的程序"？

**解决**：通过 exe 所在位置判断：

| exe 所在位置 | 判定结果 |
|-------------|---------|
| 开发环境 | 安装程序 |
| 临时目录 | 安装程序 |
| 旧版安装目录内 | 已安装的程序 |
| 其他（下载目录等） | 安装程序 |

```python
def _is_running_installer() -> bool:
    if not getattr(sys, 'frozen', False):
        return True  # 开发环境

    exe_path = Path(sys.executable).resolve()

    # 在临时目录 → 安装程序
    temp_dir = os.environ.get('TEMP', '')
    if temp_dir and str(exe_path).lower().startswith(temp_dir.lower()):
        return True

    # 检查是否在已安装的目录内
    old_install_path = _get_install_path()
    if old_install_path:
        try:
            exe_path.relative_to(Path(old_install_path))
            return False  # 在安装目录内 → 已安装的程序
        except ValueError:
            return True  # 不在安装目录内 → 新下载的安装程序

    return True
```

```python
def shutdown(self) -> None:
    """关闭日志系统，释放文件占用"""
    if not self._initialized or not self._logger:
        return

    try:
        for handler in self._logger.handlers[:]:
            handler.close()
            self._logger.removeHandler(handler)
        self._initialized = False
    except (OSError, RuntimeError):
        pass
```

#### 14.9.1 按需提权设计

**问题**：安装程序启动即请求管理员权限，exe 上显示 UAC 盾牌图标，不美观且用户体验差。

**解决**：移除打包时的 `--windows-uac-admin` 参数，改为在用户选择安装路径后检测是否需要管理员权限：

```python
def requires_admin(path: str | Path) -> bool:
    """通过尝试在目标目录创建临时文件判断是否需要管理员权限"""
    try:
        test_file = Path(path) / '.write_test_temp_file'
        test_file.touch()
        test_file.unlink()
        return False  # 不需要权限
    except (OSError, PermissionError):
        return True
```

**流程**：用户选择路径 → 检测需要权限 → 弹出确认对话框 → UAC 提权重启 → 直接进入进度页面

#### 14.9.2 Nuitka 兼容性（安装程序场景）

安装程序与主程序的打包检测方式不同：主程序资源路径通过 `sys.frozen` 判断（现代 Nuitka standalone 模式会设置该标志）；安装程序使用 `__main__.__compiled__` 检测：

| 差异 | PyInstaller | Nuitka | 后果 |
|------|------------|--------|------|
| 打包标志 | `sys.frozen = True` | 需检测 `__main__.__compiled__` | 仅查 `sys.frozen` 时可能误判为开发环境 |
| 可执行文件路径 | `sys.executable` = exe | 可能指向 Python 解释器 | `[WinError 2]` 找不到文件 |

**统一检测方案**：

```python
def is_frozen() -> bool:
    if getattr(sys, 'frozen', False):
        return True
    import __main__
    return getattr(__main__, '__compiled__', False)

def get_exe_path() -> Path:
    if getattr(sys, 'frozen', False):
        return Path(sys.executable)        # PyInstaller
    import __main__
    if getattr(__main__, '__compiled__', False):
        return Path(sys.argv[0]).resolve() # Nuitka
    return Path(sys.executable)            # 开发环境
```

#### 14.9.3 提权重启后恢复状态

**问题**：提权重启后重新启动程序，用户之前的配置（安装路径、快捷方式选项）全部丢失。

**解决**：通过命令行参数传递配置，重启后直接跳转到进度页面：

```python
# 提权前传递参数
args = f'--install-path "{path}" --desktop-shortcut --start-menu-shortcut --skip-to-progress'

# 重启后恢复
if args.skip_to_progress and args.install_path:
    preset_config = {
        'install_path': args.install_path,
        'create_desktop_shortcut': args.desktop_shortcut,
        'create_start_menu': args.start_menu_shortcut,
    }
    wizard.set_preset_config(preset_config)
    wizard.skip_to_progress_page()
```

#### 14.9.4 卸载时关闭主程序

**问题**：卸载程序和主程序是同一个 exe，`taskkill /IM` 会把卸载程序自己也关闭。

**解决**：使用 `tasklist` 逐个获取同名进程 PID，排除当前进程后逐个关闭：

```python
def _close_main_app(self):
    current_pid = os.getpid()
    result = subprocess.run(
        ["tasklist", "/FI", "IMAGENAME eq Color Card.exe", "/FO", "CSV", "/NH"],
        capture_output=True, text=True,
        creationflags=subprocess.CREATE_NO_WINDOW
    )
    for line in result.stdout.strip().split('\n'):
        parts = line.split(',')
        if len(parts) >= 2:
            pid = int(parts[1].strip('"'))
            if pid != current_pid:
                subprocess.run(["taskkill", "/F", "/PID", str(pid)], ...)
```

#### 14.9.5 第三阶段关键经验

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 管理员图标显示 | UAC manifest 嵌入 exe | 移除 --windows-uac-admin，按需提权 |
| Nuitka 安装失败 | sys.frozen 不存在 | 同时检测 `__main__.__compiled__` |
| exe 路径获取错误 | sys.executable 指向解释器 | 用 sys.argv[0] 替代 |
| 卸载关闭自身 | taskkill 关闭所有同名进程 | 通过 PID 排除当前进程 |
| 提权重启丢配置 | 进程重启丢失状态 | 命令行参数传递并跳页 |

### 14.10 卸载自删除批处理踩坑经验

**问题**：卸载完成后批处理脚本无法删除安装目录和自身，程序文件残留。

**排查过程**：问题表面症状一致（"没有删除"），但实际是四个问题串联叠加，每个修完下一个才暴露，排查耗时较长。

#### 根因一：注册表读取时机错误

卸载 Worker 线程在步骤 2 删除了注册表，但 `run_uninstaller()` 在对话框关闭后才读取注册表获取安装路径，此时注册表已不存在，返回 `None`，Popen 被跳过。

**修复**：在对话框启动前读取安装路径并保存。

```python
# 对话框启动前读取（注册表在卸载过程中会被删除）
registry_installer = RegistryInstaller()
install_path = registry_installer.get_install_path()
```

#### 根因二：subprocess.Popen 路径含空格被截断

`subprocess.Popen(str(path), shell=True)` 在 Windows 上将字符串传给 `cmd.exe /c`，路径 `C:\Program Files\取色卡\uninstall_cleanup.bat` 中的空格导致 `cmd.exe` 把 `C:\Program` 当成命令执行。

**修复**：改用列表传参，Python 的 `list2cmdline()` 自动给含空格参数加引号。

```python
# ❌ 字符串 + shell=True，路径含空格被截断
subprocess.Popen(str(batch_path), shell=True, ...)

# ✅ 列表传参，自动加引号
subprocess.Popen(['cmd.exe', '/c', str(batch_path)], ...)
```

#### 根因三：cmd.exe CWD 锁定安装目录

Windows 不允许删除任何进程的当前工作目录。提权重启后新进程 CWD 是安装目录自身，`cmd.exe` 继承该 CWD，`rd /s /q` 要删除脚下站着的目录，系统直接拒绝。

**修复**：双重保障——批处理首行切换 CWD + Popen 指定 `cwd`。

```python
# Python 端：不在安装目录启动 cmd.exe
subprocess.Popen(
    ['cmd.exe', '/c', str(batch_path)],
    cwd=os.environ['TEMP'],              # CWD 改为 TEMP
    creationflags=subprocess.DETACHED_PROCESS
)
```

```batch
:: 批处理端：第一行就搬家
@echo off
cd /d "%TEMP%"
```

#### 根因四：批处理编码导致脚本崩溃

`encoding='utf-8'` 写入的 `.bat` 文件不带 BOM，中文 Windows 的 `cmd.exe` 默认用 GBK（CP936）解析。中文全变乱码，部分乱码字节被解析为控制字符，脚本在第一行可执行代码就崩溃，后续 `ping`、`rd` 根本没执行。

**修复**：GBK 编码写入，脚本内不包含任何中文文本。

```python
# ❌ cmd.exe 用 GBK 解析 utf-8 文件 → 乱码崩溃
batch_path.write_text(batch_content, encoding='utf-8')

# ✅ 用 GBK 写入，cmd.exe 原生识别
batch_path.write_text(batch_content, encoding='gbk')
```

批处理脚本内容全部用纯 ASCII 命令（`cd`、`ping`、`rd`、`del`），不写 `echo`、不输出中文、不调用 `chcp`。

#### 调试技巧

排查批处理脚本问题时，写入诊断日志是有效手段，但注意日志文件也必须与脚本使用相同编码：

```batch
:: 在脚本首行写入诊断信息
echo [%date% %time%] START >> "%TEMP%\diag.log"
echo [%date% %time%] CWD=%CD% >> "%TEMP%\diag.log"
```

通过检查诊断日志是否存在以及行数，可以判断脚本卡在哪一步。

#### 关键经验

| 问题 | 症状 | 根因 | 解决 |
|------|------|------|------|
| 脚本未执行 | Popen 被跳过 | 注册表提前删除，路径为 None | 提前读取注册表 |
| 脚本未执行 | Popen 调了但无效 | 路径含空格被截断 | 列表传参替代 shell=True |
| rd 失败 | 执行了但删不掉 | cmd.exe CWD 锁定目录 | cd /d %TEMP% + cwd 参数 |
| 脚本崩溃 | 诊断日志只有开头乱码 | utf-8 文件被 GBK 解析 | 改用 encoding='gbk' |

**核心教训**：

- 批处理脚本在 Windows 上写入必须用系统默认编码（GBK），不能假设 cmd.exe 支持 UTF-8
- 批处理脚本调试需要有专门的诊断日志（写入文件而非依赖 stdout）
- 串联问题排查时每个修完都不能确认是否彻底解决，因为下一个问题会掩盖结果
- subprocess.Popen 在 Windows 上应优先使用列表传参，避免 shell=True 的引号陷阱

## 15. macOS 应用本地化显示名经验

### 15.1 问题背景

Mac 版应用在启动台（Launchpad）和应用简介（Get Info）中显示英文名 "ColorCard"，需要改为中文"取色卡"，同时保持 `.app` 包名为 `ColorCard.app` 以确保覆盖安装兼容。

### 15.2 踩坑过程

| 尝试方案 | 结果 | 原因 |
|---------|------|------|
| 修改 `Info.plist` 的 `CFBundleDisplayName` | ❌ 启动台不生效 | macOS 优先读取本地化文件 |
| 重命名 `.app` 为 `取色卡.app` | ❌ 无法覆盖旧版本 | 文件名不同，macOS 视为不同应用 |
| 创建符号链接 `取色卡.app → ColorCard.app` | ❌ 安装后产生两个应用 | 符号链接被当作独立文件复制 |
| `InfoPlist.strings`（UTF-8 编码） | ❌ 不生效 | macOS 要求 UTF-16 编码 |
| **`InfoPlist.strings`（UTF-16 编码）** | ✅ 完美解决 | 正确方案 |

### 15.3 正确方案：InfoPlist.strings 本地化

**核心原理**：macOS 优先读取 `.lproj/InfoPlist.strings` 中的本地化名称，而非 `Info.plist` 中的 `CFBundleDisplayName`。

**文件结构**：

```
ColorCard.app/Contents/Resources/
├── zh-Hans.lproj/InfoPlist.strings   # 简体中文
├── zh-Hant.lproj/InfoPlist.strings   # 繁体中文
└── en.lproj/InfoPlist.strings        # 英文
```

**文件内容**（以简体中文为例）：

```
"CFBundleName" = "取色卡";
"CFBundleDisplayName" = "取色卡";
```

**关键要求：**

- `InfoPlist.strings` 必须是 **UTF-16 编码**，UTF-8 不会被 macOS 识别
- 需要同时创建 `zh-Hans.lproj`（简体）和 `zh-Hant.lproj`（繁体）

### 15.4 构建脚本实现

```bash
# 创建本地化文件
LOCALES_DIR="$APP_BUNDLE/Contents/Resources"
mkdir -p "$LOCALES_DIR/zh-Hans.lproj"
printf '%s\n' '"CFBundleName" = "取色卡";' '"CFBundleDisplayName" = "取色卡";' > "$LOCALES_DIR/zh-Hans.lproj/InfoPlist.strings.utf8"
iconv -f UTF-8 -t UTF-16 "$LOCALES_DIR/zh-Hans.lproj/InfoPlist.strings.utf8" > "$LOCALES_DIR/zh-Hans.lproj/InfoPlist.strings"
rm "$LOCALES_DIR/zh-Hans.lproj/InfoPlist.strings.utf8"
```

**流程**：先用 `printf` 生成 UTF-8 临时文件 → 用 `iconv` 转换为 UTF-16 → 删除临时文件。

### 15.5 覆盖安装兼容性

macOS 覆盖安装需要同时满足两个条件：

1. **Bundle ID 相同**（`CFBundleIdentifier`）
2. **文件名相同**（`.app` 包名）

因此 `Info.plist` 中的 `CFBundleIdentifier` 必须与旧版本保持一致，`.app` 包名不能修改。

### 15.6 最终效果

| 位置 | 显示名称 | 控制方式 |
|------|---------|---------|
| 启动台（中文系统） | 取色卡 | `zh-Hans.lproj/InfoPlist.strings` |
| 启动台（英文系统） | Color Card | `en.lproj/InfoPlist.strings` |
| 应用简介（中文系统） | 取色卡 | `zh-Hans.lproj/InfoPlist.strings` |
| DMG 卷标 | 取色卡 | `create-dmg --volname "取色卡"` |
| DMG 文件名 | `Color_Card_1.0.0_mac.dmg` | 不变 |
| Finder 中的文件名 | ColorCard.app | 不变（确保覆盖安装） |

### 15.7 关键经验

| 要点 | 说明 |
|------|------|
| `InfoPlist.strings` 必须是 UTF-16 编码 | UTF-8 编码的文件不会被 macOS 识别 |
| 本地化优先级高于 `Info.plist` | macOS 优先读取 `.lproj/InfoPlist.strings` |
| 繁体中文需要单独的 `zh-Hant.lproj` | 不设置则繁体中文系统回退到英文名 |
| `.app` 包名不能改 | 改名后无法覆盖旧版本 |
| `CFBundleIdentifier` 必须与旧版一致 | 否则被视为不同应用 |
| 参考成熟软件做法 | 如 UU 远程、豆包等均使用此方案 |
