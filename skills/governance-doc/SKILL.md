# 治理文件改动

适用文件：`AGENTS.md`、`文档/开发规范.md`、`文档/专项规范/*`、`skills/*`。规则本体见《开发规范》§9.8「治理元规则」，授权口径见 §9.3，此处只写执行流程。

0. **确认范围**：列出本次要改的文件。不在上述清单内的（过程性文档、业务代码）不适用本单元。
1. **先读全**：读目标文件全文与相邻文件；检索同一约束是否已存在。重叠的改旧句，矛盾的先解冲突，不新增第二份说法。
2. **先说明，后动手**：向开发者列出「改哪句 / 改成什么 / 为什么 / 影响哪些引用」，停等明确授权；未授权前不写文件。
3. **执行**：只做授权过的改动。新增规则须有真实发生过的静默失效作为依据；优先改现有句子，不新增段落或状态。
4. **改后检查**：
   - 交叉引用：检索本次涉及的章节号与文件名，确认无断链
   - 单一真源：确认同一约束没有出现第二份说法
   - skills 改动：同步 `.trae/`、`.qoder/`、`.dsh/`、`.zcode/` 四份副本，并按**全目录**哈希校验
   - 触发表：skill 名称或触发词变化时，同步 AGENTS 触发表与该 skill 的 description
5. **报告**：列出实际改动、检查结果与未处理项。提交仍由开发者执行，本单元不提交、不推送。
